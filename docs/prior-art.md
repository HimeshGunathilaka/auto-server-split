# Prior art

Searched on 2026-10-19, 2026-10-23 and 2026-10-26 (npm search, web search, GitHub, the VS Code
Marketplace, the Next.js docs and the `vercel/next.js` repository). Terms used: "use client
codemod", "client boundary", "server component split", "RSC islands", "client component
extraction", "extract client island", "RSC boundary optimizer", "use client eslint", "unnecessary
use client", "client boundary visualizer", plus general web searches for codemods and lint rules
that split `"use client"` components. Each tool below was checked against its own README, package
or marketplace page; versions are the latest published on 2026-10-26.

**Result: nothing found that deterministically splits a `"use client"` component into a server
component plus generated client islands.** The closest is an agent skill that Next.js 16.4 ships,
which describes the same refactor as instructions for an AI coding agent. The tools that come
closest analyse, visualise or lint client boundaries; a few add or remove whole `"use client"`
directives.

## Other RSC frameworks

- [React Router RSC Framework Mode](https://reactrouter.com/how-to/react-server-components) (8.5) is
  experimental (`unstable_reactRouterRSC` with `@vitejs/plugin-rsc`) and "subject to breaking
  changes in minor/patch releases".
- [TanStack Start Server Components](https://tanstack.com/start/latest/docs/framework/react/guide/server-components)
  are experimental, off by default, and built around `createCompositeComponent` rather than
  `"use client"` files.

Both are why this tool supports only the Next.js App Router for now (see
[decisions.md](decisions.md)).

## Related guidance (manual pattern this tool automates)

- [React docs: `'use client'`](https://react.dev/reference/rsc/use-client): the directive marks a boundary in the module graph; every transitive import becomes client code.
- [Next.js docs: Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components): "add `'use client'` to specific interactive components instead of marking large parts of your UI as Client Components".
- [Gatsby partial hydration guide](https://github.com/gatsbyjs/gatsby/blob/d3b38468d54bd57e625954af29f3101df5388ce5/docs/docs/how-to/performance/partial-hydration.md): move client components to the leaves of the tree.

## Conclusion

No existing tool does what `auto-server-split` does deterministically, so building it does not
duplicate prior work. Analysers and visualisers (the Next.js analyzer, RSC X-Ray, client-creep,
RSC Boundary) show where client code comes from; directive codemods add or remove whole
`"use client"` lines. Splitting a component at the boundary, with the importer, serializability
and self-checks that make it safe, is still done by hand or by an agent following instructions.
The Next.js team recommending that refactor through an agent skill makes a verified, repeatable
implementation of it more useful, not less.
